# CP-13: child level rule, second change

Scope: `specs/CP-13/spec.md` (issue #461). Migration `20270120090000_grade_min_adults.sql`.

## What changed
- Items 1, 2, 5, 6 already held on main; their proofs are regression locks (`specs/CP-13/proofs/FIRST_RUN.md`).
- Item 3: the minimum adults is `grade.min_adults` (int, not null, default 2, above 0; K2 = 1, set for existing schools
  from the old `observed_rule.min_adults` and for new schools in `internal.observed_rules`). `state.min_adults` (threshold
  row and seed entry) and `observed_rule.min_adults` are gone. `graph_level_window` returns the child's grade minimum
  (`child.band`, read live); `graph_state_of` takes it as `p_min_adults`; `graph_observed_states` reads the grade.
  The migration recreates `child_level_state`, `level_calibration` and the grants around the changed signature.
- Item 4: `public.graph_state_changes(p_child)` (stable, counts by grade and transition) and
  `engine graph --changes`. Neither writes. `workflows.json` is unchanged: its check accepts sub-commands, not flags,
  and `engine graph` is already named on N10.

- A value a school tuned for `state.min_adults` moves to that school's grades before the row is deleted (K2 takes
  `observed_rule`'s). `checks/rules.json` regenerated from a database built from the migrations alone
  (`engine live rules --write --url <throwaway>`; pass `--url`, the default is the live database).
