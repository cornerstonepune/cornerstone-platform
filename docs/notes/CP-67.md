# CP-67 — Curriculum as one tree (issue #827)

State on 17 Nov 2026, branch `cp-67-curriculum-tree`. Handed over at the context limit; the next session builds the screen.

## The bug, at its cause (read on the live database)
Grade 2 → Maths shows nothing because `app/(app)/setup/curriculum/flow.tsx` loads objectives only once a topic is chosen, and its
topics come only from `learning_objective.topic_code`, empty for every active objective (Grade 2 Maths: 122 objectives, 0 with a
topic, 24 units). The topic level is the objective's `unit` (2,591 of 2,593 active objectives have one).

## Done on this branch
- `apps/web/lib/curriculum-tree.ts`: `branches(grade)` gives every subject of a grade with its units and counts (objectives,
  distinct activities); `leaves(grade, subject, unit)` gives a unit's objectives. An objective with no subject or no unit sits under
  "No subject yet" / "No unit yet" (key `-`). Checked on live, read only: Grade 2's rows sum to 483 = its 483 active objectives.

## The screen (built 17 Nov)
- `app/(app)/setup/curriculum/tree.tsx` replaces `flow.tsx` (deleted): grades as the shared segmented control (`.b-seg`); subject rows with
  two count chips (`.chip`) and a chevron; unit rows; compact objective rows. Every row is a link: the open path is the address
  (`?grade=G2&subject=NUM&unit=…&open=objective:<code>`), so one subject and one unit are open at a time and a reload keeps the path.
- The objective opens the page's existing `DetailPanel` (`objectiveOpened`). The "Choose / Appendix / To review" toggle is now a row of
  quiet links. Only shared classes and design tokens; no new CSS (CP-68 restyles the shared pieces centrally).
- Motion: the chevron turns in 150 ms ease-out, none under reduced motion.
- Tests: `tests/u106-curriculum-tree.spec.ts`, five `@core` tests, one per *Done when* 1–5; line 6 is u90. u104 tests 1–2 read the old
  flow's chips, so they now read the tree (path, leaf, panel) and the appendix's Objectives table (capability, words, machine mark).
