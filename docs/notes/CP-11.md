# CP-11: the timetable generator (FET)

Scope: `specs/CP-11/spec.md` (issue #459). Design: `specs/CP-11/design.md`. Nothing educators see changes; putting a draft
live is CP-21.

## Verified
Filled in at the end of the build with the commands and their output (see the pull request for the numbers).

## What was built
- `supabase/migrations/20270121090000_timetable_run.sql`: `timetable_run` (append-only), and the per-school settings
  `timetable.solve_seconds` (120) and `timetable.seed` (20261109).
- `engine/adapters/fet.py`: the only file that names FET. Writes the input file, runs `fet-cl` with the time limit and
  the seed in all six components, returns FET's `_activities.xml` byte for byte.
- `engine/w2_print/tt_need.py`: days (holidays out), the frame, the lessons each subject needs once limits are applied,
  the checks that name the rule. `engine/w2_print/tt_generate.py`: builds FET's plan, runs it, decides the outcome, keeps
  the run. `bin/engine timetable generate --grade --section --year --fortnight [--dry]`.
- Dockerfile: the build now fails if `fet-cl` is missing (the old `fet-cl --version | head -1` passed whatever happened).

## Choices worth knowing
- **Access classification.** `timetable_run` holds no child, so the migration lists it in `access_table` as `school_wide`, as
  CP-4 requires (like `timetable_slot` and `timetable_block`). Its migration is numbered after CP-4's.
- **Unmeetable by the checks: `placed` is 0.** FET is not run, so nothing was placed; the report carries the free periods.
- **Pinned and blocked cells** are FET "not available" times for the class; a subject with a week limit is held to its
  week's days; a subject falls at most once a day when its lessons fit in the days that have a free period.
- Timetable text in the report (block reasons) is the school's own words, entered by staff; no name is added.

## Harness change (approved by Nimish, 9 Nov 2026, relayed by the orchestrator)
`.claude/athena/setup.sh` gains one step inside the `GITHUB_ACTIONS` branch: `sudo apt-get update -qq && sudo apt-get
install -y --no-install-recommends fet && fet-cl --version …` (the version is written to a file and its first line shown,
because `fet-cl --version | head -1` under that script's `set -o pipefail` would end the script on a broken pipe). Without it
the Athena job has no `fet-cl` and proofs 2 to 5 fail. This is a platform-only edit: the installer copies `setup.default.sh` to
`setup.sh` only when `setup.sh` is missing, so an Athena update does not undo it (the Athena coordinator checked, 9 Nov).
