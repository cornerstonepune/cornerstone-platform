# CP-59: Delayed lessons

Branch `cp-59-delayed-lessons` (on `cp-58-…` on `cp-57-…`). No migration.

- The engine's `tt_move` refuses a source day gone by, a target in another fortnight and a lesson not planned, so a delayed lesson
  could not use it. `tt_delayed.move_delayed` reuses `tt_move`'s own places, writer (materials links follow) and history row, adds the
  rules for a delayed lesson (past, planned, not fixed; target a free place, today or later), and runs all in one transaction.
- The word "carry" is banned on screens (school words: regroup, never carry), so the route is `/timetable/delayed`.
- Web: `lib/delayed.ts` (not taught, free places, ledger), `timetable/delayed/page.tsx`, a `delayed` case in `api/timetable/[action]`.
  A target week the class has no lessons placed in yet offers no places (its fortnight is not made); the page says so.
- Rejected: swapping into a planned lesson (it would push that lesson into the past).
- Access (orchestrator, 16 Nov): a coordinator any class; an educator her own classes only, with the timetable switched on for her (not while she only previews). The engine route checks it (`sees_all`, else `k2_day.my_classes`), so the web page can offer nothing wider.
