# CP-55 — pages stop re-reading the question bank per skill; "Forgot your password" tells the truth

Issue #777, spec `specs/CP-55/spec.md`. No schema change (CP-54 holds the database).

## Verified

- **Cause, from live's own records (16 Nov 2026).** Vercel: one error group, `DatabaseSlow`, 32 times in 7 days, 7 users,
  on /setup/skills/approve, /setup/question-bank, /, /setup/curriculum, /children/assessments. Region is not it: Vercel
  `bom1`, Supabase `ap-south-1`. Supabase's postgres log: the skill-list query (`skillSets`) at 10,559 / 30,118 / 11,321 /
  15,953 ms between 08:07 and 08:41 UTC; its logged plan reads `item` and `sheet_template` in per-skill SubPlans.
  `pg_stat_statements`: four variants of that query, mean 3.9–6.1 s, max 30 s.
- **Before / after on live (read-only EXPLAIN ANALYZE, same moment):**
  | | before | after |
  |---|---|---|
  | list of skills (Skills approval, Curriculum, skill pages) | 10,087 ms, 102,938 pages | 143 ms, 7,293 pages, no bank read |
  | counts for all 155 skills, where a page shows them | inside the 10 s above | 5,804 ms cold, then 84 / 65 / 64 ms |
- **Why a one-pass count can still be slow on live:** the same count of 43,513 questions took 903, 334, 41, 41 ms in a
  row, and 6.3 s a minute later. The 1 GB database does not keep the 137 MB `item` table in memory. I don't know for
  certain whether it is swap or something else; the measured effect is that a cold read costs seconds.
- **Mail:** live `password_link`: 9 rows, all `reset`, all `not configured`, 28 Oct to 16 Nov. `engine live watch` already
  says "mail is not configured, so N set-password links … were never sent" (`checks/watch.py`); now tested.
- **Tests:** `p55-reads-the-bank-once.spec.ts` 4/4 pass on a `bin/testdb fresh` copy (28,699 questions) and **4/4 fail
  on the old `lib/queries.ts` + `lib/queries-bank.ts`**; `p55-forgot-tells-the-truth.spec.ts` 3/3; `test_watch.py` 8/8;
  `bin/check` 67 passed; tsc and eslint clean (bar the existing `LayoutProps` typegen gap).

## Handoff

- Live after merge: Skills approval, Curriculum and a skill's page no longer read the bank; Question bank, class maker,
  custom paper and Curriculum › Skills read it once per table, not 155 times.
- **Next, blocked on CP-54 merging (schema):** the counts still read the 137 MB table once (5.8 s cold). The fix is a

  'generated'`, or a CHECK `source = 'generated' or skill_set_code is null` so the existing 0.9 MB `item_skill_set_idx`
  answers alone (it needs `item` vacuumed: 17,007 heap fetches today). Its own spec.
- **Nimish:** add SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, SMTP_FROM in Vercel; until then the page says email is
  not set up. The database's memory (1 GB) is a cost decision.
