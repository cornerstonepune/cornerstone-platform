# CP-20: a throwaway database in the proofs job

Branch `cp-20-proofs-job-database`. Scope `specs/CP-20/`. The only product change is `.claude/athena/setup.sh`: a block gated on
`GITHUB_ACTIONS=true` that runs `bin/ci-postgres`, then `bin/testdb fresh` in the background while `npm ci` runs, and appends
`TEST_DATABASE_URL` to `$GITHUB_ENV` only after the build exits 0. `DATABASE_URL` is never assigned.

## What reads `TEST_DATABASE_URL` (checked by grep, 8 Nov 2026)

Once set job-wide, each of these now runs against the throwaway database in the proofs job:

- `packages/engine/tests/conftest.py`: when set, overwrites `DATABASE_URL` from `db.local_copy()` for every engine test;
  exits if only `DATABASE_URL` is set. This is why only the TEST variable is exported.
- `packages/engine/engine/core/db.py` (`local_copy()`): reads it; refuses a non-loopback host.
- `packages/engine/engine/checks/done.py`: reads it from `os.environ` when building a proof's environment.
- `packages/engine/tests/test_test_database.py`: first test skips when it is unset (done-when 4: none skipped in the job).
- `packages/engine/tests/test_image.py`: strips it from the environment on purpose.
- `bin/check`: blanks both variables for its no-database line, so it is unaffected.
- `.claude/athena/fast-checks.sh` and `apps/web/playwright.config.ts`: the fast checks only `playwright test --list` with a
  loopback default; the config refuses anything but a local copy.
- `bin/testdb`: its non-`fresh` modes read it from `.env`; `fresh` takes the URL as an argument.

## Facts confirmed

- `.github/workflows/athena.yml`: `runs-on: ubuntu-24.04`, `timeout-minutes: 30`. Neither is touched.
- `bin/ci-postgres` installs Postgres 17 from the PostgreSQL apt repository on 127.0.0.1:5432 and refuses outside CI. It
  extends `$GITHUB_PATH` only for later steps, so setup.sh puts `/usr/lib/postgresql/17/bin` on its own `PATH` before
  `bin/testdb` (which calls `psql`).
- Chromium: `ci.yml` installs it separately (`uv run playwright install --with-deps chromium`) for tests that print papers.
  `engine library build` only inserts `sheet_template` rows (`w2_print/library.py: build`); rendering is `library.pdf()`,
  never called by `build`. `bank refill` imports no renderer. So the database build needs no Chromium and setup.sh installs none.
- Time, measured in GitHub's job (athena run 33, head e6435290): the `proofs` job took 5 min 50 s (10:10:34 to 10:16:24),
  against a 30-minute limit and the 25-minute stop line. The first run (head f8074a5) took about 8.5 min and had a cold
  cache. `ci.yml` records about 4 minutes for the database build in a browser shard.
- Proof 4 in the job: `CP-20: PASS`, all six proofs, including `4 test_test_database.py runs and passes in the job with
  none skipped`, with `TEST_DATABASE_URL` at 127.0.0.1:5432.
- Catch-22 found: CI re-proves only specs whose status is `built` (`athena done --all`), and `athena finish` needs every
  proof, proof 4 included, to pass first. So the first job run (head f8074a5, status `locked`) did not run CP-20 at all. Here
  it was solved by building a throwaway Postgres 16 (not 17) on loopback in the session with `bin/testdb fresh`, running
  `athena finish` with `TEST_DATABASE_URL` pointing at it, and deleting it. Any later scope whose proof needs the job's
  database meets the same trap.
- The bare `( cmd; echo $? >rc ) &` from `ci.yml` would hang under setup.sh's `set -e`; the subshell here sets `rc=0` and
  uses `|| rc=$?` so the rc file is always written.
- "Athena never overwrites setup.sh" rests on its header and on it having no entry in `.claude/athena/MANIFEST.json`
  (proof 5 checks the latter). It is not verified against the installer in athena-ops.
