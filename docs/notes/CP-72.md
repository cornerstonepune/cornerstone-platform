# CP-72: Curriculum opens instantly (issue #842)

## Verified

- `npx playwright test u107 --project=steps` (local copy, production build): 6 passed, one per Done-when line.
- Curriculum specs run beside it (u106, u104, u17, u19, u42, u5, u12, u52, u95, u74): all pass except u42's question-bank total
  ("of 5,807"), which fails identically on main against a freshly built local copy (a seed-count difference, not this change).
- `bin/check`: 72 passed, 4 skipped.

## What changed

- The tree page (`flow.tsx`) reads only the tree: `lib/curriculum-cache.ts` keeps one read per grade (subjects, units, objectives) with
  Next's `unstable_cache` (Next 16.4.5's docs mark it as replaced by `use cache`, which needs the whole app on Cache Components; a change
  of its own). Refreshed 60 s after it was read, and at once by `curriculumChanged()` (`updateTag`) from the website's curriculum edit actions.
- `tree-view.tsx` (client) opens and closes subjects and units and switches grades with `history.pushState`: no server request.
  Objective rows prefetch themselves (`prefetch`); the panel reads that objective only.
- Appendix and To review are unchanged and read their own when opened. A skill opened by an old address still takes the long path.
- A failed or slow tree read is a quiet line with "Try again" (`EmptyState`), never the page error.
- Test hooks (`lib/test-hooks.ts`, `/api/test-hooks`, on only with `TEST_HOOKS=1`) note each read and can slow or refuse one.

## Handoff

- Two small look differences, both from not reading the heavy sets on a click: the "To review" link on the tree has no count (the review
  view still shows every count), and the "N questions wait" line is gone from the summary band. The three figures on the band stream in
  after the tree, from what is kept.
- Walking the tree keeps the open objective's panel open (it used to close it).
- The engine writes behind the website's back, so its changes show in the tree within 60 s; the website's own edits show at once.
- The access gate is deliberately not kept (a grant taken away must stop at once); the tree does not need it, only a panel does.
- The app frame's menu badge (`asksWaiting`) is read on every page; out of scope here.
