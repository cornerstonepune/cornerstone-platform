## 1. Where a lesson's preparation comes from

A lesson is a `session` row (class, school day, period). Its activity is
`coalesce(activity by session.activity_code, plan_entry.activity_id)` (`w2_print/k2_day.py`, `apps/web/lib/period.ts`).

| Part | Stored in | Read by (already exists) |
|---|---|---|
| Objective(s) | `activity.objective` (one text) and `activity_objective` → `learning_objective.title` | engine `/timetable/activity` (`k2_day._activity_detail`), web `lessonActivity`; page part `objective` via `/curriculum/page/read` (`pageOf`) |
| Activity and steps | `activity.steps`, `activity.steps_list` | the same two reads; `StepsPart` in `components/lesson-panel.tsx` |
| Materials | `activity.materials` (text) and `activity_material` → `material_item` (name, quantity, unit) | `pageOf`; `MaterialsPart` |
| Rubric | `activity.level_0` … `level_3` (the panel already titles these "The rubric": `RubricRows`) | `lessonActivity` (`levels`) |

The `rubric` table is a different thing: 7 rows for English question types, used in marking, not per activity.

Everything for one lesson is already gathered by `lessonView(me, sessionId)` (`apps/web/lib/lesson-view.ts`), and the parts
`OutcomePart`, `StepsPart`, `WatchPart`, `RubricRows`, `MaterialsPart` are exported one by one from `lesson-panel.tsx`.
My day reuses those; it does not read an activity a second way.

### K2 against G1–G4

The whole lesson chain (timetable load, `plan_entry`, `session`, page parts, materials rows) is loaded for K2 only. There is
no grade branch in the code: a G1–G4 class simply has no sessions, so its day comes back empty. G1–G4 teaching is recorded as
topics and skills taught per class (`class_topic`, `class_skill`), with no day or period.

### Whose lessons a day returns today

`POST /timetable/day` (`k2_day.day`) returns **one class**: her first, unless a `class_id` is passed.
- class teacher: every period of that class;
- subject educator: her first class only, narrowed to her subject's periods; other classes need a call each;
- coordinator with no class: refused ("No class is yours on this day.") unless she names a class.

No read exists for "one person's lessons across her classes" or "the school's lessons on a day". `session.led_by_staff_id`
exists but is empty on every live row, so "her lessons" can only come from her grants (class, subject), as `k2_day` does now.

## 2. The task kinds: how urgency is decided, and whether finishing is recorded

Urgency today is **fixed per kind** (`KINDS` in `apps/web/lib/todo.ts`, `SCHOOL_URGENCY` in `lib/today-waiting.ts`).
Nothing is dated: no kind has a due day. The one time-based state is a K2 note past `voice.confirm_within_hours` (48),
which the engine's `/k2/todo` puts in `left_unconfirmed`.

| Card | Column (from today's rank) | Finished is recorded in | In Done? |
|---|---|---|---|
| Answers to check (`check`) | Do now | `read_correction.created_at`, `by` | yes |
| Scan to read again (`empty`) | Do now | `flow_run.finished_at`; no class | yes, school-wide only |
| Clash (school) | Do now | `approval` kind `timetable_clash`, `created_at` | yes |
| Notes left too long (school / her own) | Do now | as a note, below | yes |
| Paper to sign off (`signoff`) | This week | `item_result.confirmed_at`, `confirmed_by` | yes |
| Class paper to approve (`classpaper`) | This week | `sheet_instance.approved_at`, `approved_by` | yes |
| Home assessment to approve (`home`) | This week | `sheet_instance.approved_at` (kind `focus`) | yes |
| Parent report to approve (`report`) | This week | `approval` kind `parent_note`, `created_at` (the note has no time of its own) | yes |
| Question to answer (`ask`) | This week | `ask.answered_at`, `answered_by`; no class, no subject | yes |
| Note to confirm (`note`) | This week | `pii.educator_note.status_at` when `confirmed`; class on the note | yes |
| Timetable draft to approve (school) | This week | `approval` kind `timetable_live` | yes |
| Materials with no quantity (school) | This week | `change_log` (`materials_line`, op `quantity`) | yes |
| Topic to mark as taught (`taught`) | When ready | `school_class.taught` → `{by, at}`, latest value only | yes, but un-marking erases it |
| Assessment to make (`generate`) | When ready | `sheet_instance.created_at` (kind `assessment`); who is not recorded | yes |
| Note to record (`record`) | When ready | nothing: the row never leaves | **no** |
| Lessons not done last week (school) | When ready | nothing: `session.state` has no time and nothing writes `done` | **no** |

`approval` (append-only, with `created_at`) is the one clock for most approvals; `changedLately` in
`apps/web/lib/setup-overview.ts` already reads it and is the pattern to copy. No "recently done" list exists anywhere yet.

Skills to approve stay off the page, as on Today now (specs/UI-7 #3).

## 7. Two faults found on the way (rule 11), fixed in this branch

- **"Notes left unconfirmed" counted the wrong thing.** The school's row took `k2_reads._counts()["late"]`, which counts
  observations confirmed on a later day than they were observed. Notes still waiting past `voice.confirm_within_hours` were not in
  it. Live shows 0 for both today (no notes exist yet), so nobody was misled yet. Now `k2_reads.left_unconfirmed()` counts the
  notes, by the same rule `_notes` gives a note its `left_unconfirmed` state; `today_school` uses it. Tests:
  `test_today_school.py::test_11` (fresh, confirmed and late-confirmed are not counted; equal to the notes' own states) and test_4.
  `_counts()["late"]` stays for the coordinator's own page, where its meaning is documented.
- **The materials list ignored a coordinator-chosen activity.** `materials_list._source_rows` joined only the planner line's
  activity; it now takes the lesson's own `session.activity_code` first, as `k2_day` does. Test:
  `test_materials_list.py::test_an_activity_a_coordinator_chose_for_the_lesson_feeds_the_list`.
