The census of live is `CP-27-census.md`. This note is the branch's own (docs/notes/README.md).

## Group 1: word lists become rules, and tables nothing uses leave

Migration `20270125190000_cp27_word_lists_and_dead_tables.sql`, one transaction under `db push`. Tables in `public` and
`pii`: 170 → 150; functions in `public`, `internal` and `pii`: 159 → 152 (`supabase/table-budget.json`).

A table with rows on live is never dropped: what is needed is copied, a block raises unless every value is in its new
home, and the table moves to the schema `retired` (no grants, keys, triggers or policies). The three empty ones are
dropped after a block raises unless each is still empty. An unknown word anywhere rolls the whole migration back
(rehearsed: an extra `note_status` row left 170 tables and no `retired` schema).

## Group 2: one settings table, one history log

Migration `20270125200000_cp27_settings_and_history.sql`, one transaction. Tables in `public` and `pii`: 150 → 142;
functions in `public`, `internal` and `pii`: 152 → 129 (`supabase/table-budget.json`). Same rule as group 1: a table with
rows is copied, a block raises unless every row is in its new home, then it moves to `retired`.

| Table | Live rows (census) | Now | Where it went |
|---|---|---|---|
| `threshold` | 101 | retired | `config` rows, same key, the value a JSON number (`numeric` → `jsonb`, trailing zeros trimmed); `unit` was read by nothing |
| `observed_rule` | 1 | retired | columns `grade.secure_level`, `secure_days`, `recheck_days` (all three or none) |
| `observed_weight` | 2 | retired | the setting `observed.weights`, by grade |
| `approval_kind` | 3 | retired | a check on `approval.kind`; "reaches a parent, so needs a second person" is `kind = 'parent_note'` in `approval_list` |
| `validation_rule` | 2 | retired | nothing: only the `kind_stage` view (dropped) and one test read it |
| `validation_stage` | 4 | retired | nothing: only the vocabulary loader and the same test |
| `curriculum_edit` | 4,232 | retired | `change_log`: one row each, `origin` = its `changed_by`, the field as the key of `before`/`after` |
| `skill_set_version` | 93 | retired | `change_log` rows of `skill`, the old rule in `before` |
| `skill_level_version` | 76 | retired | `change_log` rows of `skill_level` (`row_id` = `skill difficulty`) |

Each moved history row carries `reason = 'CP-27: kept in <table> until 2026-11'`, and the migration counts them.

**Settings.** `config` holds every setting. `core/settings.py` is the one reader: `config`, `threshold` (a number),
`numbers` (every number under a prefix), `every` (every setting under a prefix), `many` (several keys in one read),
`put` (a writer, used by tests), `lock`. The digit reader runs apart from the engine and imports none of it, so its
caller hands it the `read.*` numbers. The K2 picture finds who is asking in the same read as the class, so reading its
three settings through the one reader keeps the page at the same number of queries.
A reader without a school reads the engine's own school's row (a new school now has copies of every key). The 15 direct
`from threshold` sites and about 25 direct `from config` sites in the engine moved onto it; `tests/test_settings.py`
fails on any other reader. The SQL readers (`graph_level_window`, `graph_state_of`, `next_difficulty`, `kind_trust`,
`level_calibration`, `graph_observed_states`) read `config` with the same defaults; `kind_trust`'s gate is now each
school's own. `child_state.why` keeps its `{key}` tokens (the keys did not change). The website's 16 readers moved to
`config` (`value::numeric`; the guide reads only number settings). Twelve `*_on_new_school` settings functions became
one, `internal.school_settings_on_new_school`: a new school copies every setting of the first school, except its list of
people (`app.staff`); K2's observed rule is in `internal.school_vocabulary`'s grade rows. The first school of a fresh
database gets its settings from the seed, as before (`engine load --check`: config 170 = 69 + 101, unchanged on a second
run).

**History.** `change_log(id, tenant_id, table_name, row_id, op, before, after, staff_id → staff, origin, reason, at)`,
refusing update and delete (`internal.forbid_change`), written by one function, `internal.change_kept(key columns,
watched columns…)`, on `activity`, `learning_objective`, `activity_skill`, `activity_objective`,
`learning_objective_skill`, `skill` (its rule) and `skill_level` (its words). One change is one row: an update keeps the
changed columns only; a link moved in place is one row from the old code to the new (it was a removal and an addition).
`origin` keeps where it came from (`app.changed_by`: the upload's label, the seed's, `staff:<id>`, `machine:… staff:…`),
so the K2 upload still tells a person's edit from its own (`k2_upload.snapshot`); `staff_id` is the member of staff named
by `staff:<id>`, else the website's signed-in one. `skill_set_version_on_change` still bumps the version and withdraws
only the edited level's approval; the old rule is kept by the log. `rehome` no longer deletes history. Reader:
`core/history.py` (`by`, `of`).

Left for later groups, each because its reader decides behaviour and its home is another group's:
- `english_sample_edit` (0 rows): its current value is the view `english_sample_now` (newest edit wins, read by the
  English page and `generate`), so it moves with the one sample table (`english_sample` + `maths_sample`) and
  `skill_level_kind_change/stop` (group 3), where the edit becomes the row plus a log row.
- `paper_edit` (0 rows): `edit_paper.newer` follows its chain; it is child data (key `child_id`) while `change_log` is
  school-wide, and its "who" is an email. It moves with group 4 (who did it, a child's data), with a `replaced_by`
  column on `sheet_instance` as the current value.
- `fortnight_edit`, `timetable_rule_edit` (group 5) and `materials_line_edit`, `materials_consolidated_change` (group 6):
  their writers and readers are those groups' tables.

Tests rewritten because they named a removed table (old → new):
