# CP-12: the timetable by hand

Branch `cp-12-build` from main (fd777c84). Scope `specs/CP-12` (PR #485), design `specs/CP-12/design.md`.

## What was built
- Migration `20270125180000_a_lesson_moved_by_hand_is_kept.sql`: `timetable_move` and `timetable_clash_accept` (both
  append-only), the view `timetable_clash`, the function `timetable_fortnight_layer(class, fortnight)`, and two settings
  per school (`timetable.open_clash_blocks_approval` on, `timetable.accept_clash_group` everything). Both tables are in
  `access_table`; the move table is class data (reach of `enrolment`), the acceptance is school-wide.
- `w2_print/tt_move.py`: a move swaps what two dated cells hold; their lessons follow, keeping id, plan line and
  materials lines (a swap takes the two lessons out together and puts them back, as CP-22's `tt_live._write` does, since
  the session key is immediate). Every check runs first; the whole move is one savepoint, so a refusal writes nothing.
- `w2_print/tt_clash.py`: the clash list, the open count by kind, and `accept`.
- Commands: `engine timetable move | accept | clashes` (`cli_tt_hand.py`), `engine fortnight approve` (`cli_fortnight.py`).
- Keyed routes `POST /timetable/move` and `POST /timetable/clash/accept`, one test each; `engine-routes.ts` regenerated.
- Tests: `test_tt_move.py`, `test_tt_clash.py`, `api/test_timetable_hand_routes.py`, world in `tests/tt_hand_world.py`.

## Decisions
- The dated layer: CP-22 built it in Python, with no database function, so `timetable_fortnight_layer` is new here
  (a copy of the frame onto the fortnight's teaching dates, once, no rows if a layer exists).
- A clash key is an md5 of kind, fortnight, cells, rule and its numbers, and the count.
- Accepting needs a current grant in the group named by `timetable.accept_clash_group` (Nimish 8 Nov), checked with the
  school's day, like CP-22's go-live group.
- Frozen fortnight: `fortnight_cycle.ensure_editable` runs inside the move's savepoint, so a refused move leaves no record.
