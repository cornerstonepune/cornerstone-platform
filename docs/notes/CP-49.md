# CP-49 backend: the level each child reached in a lesson

Part of #739 (backend: Done when 4, 5, 6). The frontend owns the other lines.

## What and why

The educator marks, from the lesson page, the level (0 to 3) each child reached, or that the child was absent or not
willing, and may set "the rest" in one go. Two engine routes, wiring only; the work is `w3_read/lesson_level.py`.

No schema change, no new table. A mark is an `activity_observation` (route `form`, the only other value the route CHECK
allows besides `voice`; entry mode `individual`; outcome `as_expected`; `reached_level` = `expected_level` = the level;
absent / not willing have no level, `expected_level` 0 because the column is NOT NULL). A level is evidence on each skill
of the lesson's activity when `voice.level_mark` has a mark for it (today level 0 maps to `not_yet`; nothing special in code).

## Routes (contract v1, engine key, `actor` is the staff email)

- `POST /lesson/level` `{actor, class_id, session_id, day?, marks:[{child_id, level}|{child_id, status}], rest_level?}`
  gives `{confirmation_id, written, evidence_written, activity_has_no_skills}`.
  403 not allowed, 404 lesson not in class, 409 lesson has no activity, 422 child not enrolled that day or bad level/status.
- `POST /lesson/level/read` `{actor, class_id, session_id}` gives `{activity_code|null, marks:[{child_id, level|null,
  status|null, confirmation_id, by: you|another, marked_at}]}`; no names.

Rules: `rest_level` marks every child enrolled that day with no current mark on the lesson; marked children keep theirs.
A change inserts a new row whose `supersedes` is the current one (reason "level changed"); nothing is updated or deleted,
old evidence stays and readers already skip superseded observations. The same mark sent again writes nothing.
Authorisation (not gated on `voice.screens_enabled`): a recording role on the class (`voice_intake.may_record`), or a
coordinator who reads the class (`educator_gate.sees_all` + `a_class`, the `/timetable/activity` rule). The lesson's
activity is `session.activity_code`, else the planner line's activity (as `k2_day` does). A change keeps the activity of
the row it replaces (the supersedes foreign key requires it).

CP-48 note, not done here: a `plan_entry.activity_id` always carries a `link_rule` (`exact_name` or `person`); if CP-48
decides a `person` link is not safe to write evidence on, the fallback here is where to apply it.

## Read route additions

`/lesson/level/read` also returns:

- `roll: [{child_id, sr_no}]`: the children enrolled in the class on the lesson's day, from `voice_intake.enrolled`, the
  same call the write uses for its 422. `sr_no` is the enrolment's roll number (there is no other serial column), ordered
  by number. Test: `test_the_roll_is_the_children_the_write_accepts_and_no_other`.
- `last: {session_id, day, counts{"0".."3", absent, not_willing}} | null`: the most recent earlier lesson (day strictly
  before) of the same class on the same activity that has marks, counted from current (non-superseded) rows. An earlier
  lesson nobody marked is passed over (it is no last time to compare with); null when there is none; the lesson itself is
  never its own last. Tests: `test_last_counts_...`, `test_last_skips_an_earlier_lesson_nobody_marked`.
