# CP-10: voice on: a voice note joins the typed path, safe without the Sarvam letter

Branch `cp-10-scope` (PR #506). Scope and design: `specs/CP-10/`. Migration `20270125130000_voice_cleanup.sql`.

## What was already there
Recording, Sarvam, draft lines, Confirm, `activity_observation` with `route='voice'` and its evidence. A voice note and a
typed one already meet in `activity_observation` and `evidence_event`; CP-10 proves it (proof 6) and changes only what
happens to the raw copies and to Sarvam's letter.

## What was built
- **Clean-up** `voice_intake.cleanup(conn)`: every note past `voice.confirm_within_hours` (48) loses its recording, then its
  transcript. Order matters: files first, rows second, and a transcript is cleared only once its recording is gone.
  A recording that cannot be deleted fails the run (counts-only message) and the note is tried again at the next run.
  A recordings folder that is not a readable folder fails the run before anything is cleared (an unmounted disk never
  reads as "all deleted"). A recording with no note and older than the cut-off is deleted too.
- **A durable record** on each note's own row: `audio_deleted_at` and `transcript_cleared_at`, set once, never changed
  (the trigger keeps the first value), beside `id` and `received_at`. No content, no name.
- **Her free sentence** is kept: `educator_note.sentence`, written at confirm (`voice_note.sentence`); the child's page
  reads it from there, so it outlives the transcript. A note confirmed before this change has its sentence copied across
  by the first clean-up that reaches it.
- **`note_claim.words` is no longer written** (nothing read it). The column is nullable; the migration cleared the
  existing values once. `note_claim` stays append-only, with no new trigger.
- **Route and schedule**: `POST /voice/cleanup` (hour as the idempotency key; a failed run is retried by the next call,
  even in the same hour), `n8n/workflows/f5-voice-cleanup.json` (hourly, one HTTP node, no Code node).
- **Commands**: `engine read voice cleanup` (replaces `retention`), `engine read voice status`.
- **Sarvam's letter is a setting, not a gate**: `voice.sarvam_no_retention_confirmed` (false). Recording goes on without
  it. `engine read voice switch sarvam on --by EMAIL --ref REFERENCE` records it, signed and logged under the staff id with
  the reference (the reference lives only in `access_log`). `status` prints "Sarvam no-retention: confirmed|not
  confirmed" and the last clean-up run.
- **Register**: the voice entry's `how_long` carries Nimish's words of 9 Nov, verbatim.
- `voice.audio_retention_days` (O-14) is retired; the root cron line for `retention` in `m1-01-voice-intake.md` is gone.

- Existing finished notes whose transcript is already gone before this change cannot have a sentence recovered; none
  exist (recording was never switched on live).
