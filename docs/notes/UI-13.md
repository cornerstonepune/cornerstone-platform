# UI-13: the frame and the inventory test

Branch `ui-13-frame`, issue #525, from `ui-14-tokens-fonts` (tokens). Scope: `specs/UI-13/spec.md`.

## Decisions (mechanical, taken by the builder)

- **AppFrame is two parts.** `components/app-frame.tsx`: `AppFrame` (the (app) layout: bar, door row, main, foot link, bottom doors)
  and `Screen` (the page: trail, eyebrow, h1, purpose, one main action, rail, next step). `Screen` replaces `PageShell`; the
  small parts (`Panel`, `Pill`, `PageHeader`, `Body`…) moved from the deleted `components/shell.tsx` to `components/parts.tsx`.
  `components/educator/crumbs.tsx` became `components/trail.tsx`: two fixed levels, the door and the thing, drawn by `PageHeader`
  from the page's title, so no page passes a trail any more.
- **The lit door is the walk's** (`components/frame/walk.tsx`): a clicked door starts a walk; any other link inside the frame
  keeps it; a page opened cold lights the door its route is mapped to in `lib/menu.ts`. Full page loads hand the walk over
  in `sessionStorage` for 15 s.
- **Doors vs `isBuilt`.** `merged_slices` is empty today, so literally "draw nothing for a target not built" would remove every
  door. A door opens its screen once built (`lib/built.ts`, `screenHref`), and until then the first page of the door that
  exists. A rail edge or a link by screen id draws nothing while its screen is unbuilt. `design-system/built.json` is made from
  `screens.json` by `scripts/tokens.mjs` (the site cannot read `docs/` at run time); `u14` checks it stays current.
- **The site follows the system's dark setting** now: `data-scheme="light"` left `<html>`. The frame, BrandMark and every page
  are on tokens (UI-14), so dark works; the full-page baselines are light.
- **Door pages row.** A door's pages sit in a row under the bar (the old group tabs), so every old page is at most two clicks
  from a page. Pages that had no Guide page when the doors were made are written `{ label, href, match, guide: false }` in
  `lib/menu.ts` (the engine's `test_guide.py` reads the entries written `{ href, label`); their "?" opens the Guide's front.
- **Acting as** is a cookie view (`lib/acting-as.ts`): it hides Setup for a coordinator. It changes nothing a query returns
  (queries are out of scope); the screens that read a scope take it up when they are built.
- **Search** is `POST /api/search` (JSON body), `lib/search.ts` `suggest`, five at most, scoped by `staff_sees`. The old
  server action `find` and its results list are gone.
- **Phone bar.** The person's parts (name, acting as, help, sign out) fold into one button at 700 px and under.
- **Focus ring.** A global `:focus-visible` outline of 2 px (generic check 5 found links with none).
- **`tests/fake-names.ts`** is the one list the inventory test allows (copied from `fake-names.json` of the wireframe kit,
  PR #539). Older specs still make their own invented first names; they are not rendered by any screen the inventory opens,
  and moving them is not this slice.
- **Not built in the inventory test yet:** the Empty check (9) needs a fixture's empty class and a screen that states an
  empty text, and the Themes check (10) needs a committed baseline per screen; both start with the first real slice
  (UI-3 or later). The ten checks otherwise run as written: see `tests/inventory/checks.ts`.

## Route walk (Done when 5)

`tests/u13-route-walk.spec.ts` follows the links each page draws from the bar, three clicks deep. Ten routes are not reached
in the test database and are listed in the test with their reasons (redirect targets, rows a timetable or a printed paper
would give, links four clicks down); each must still open.

## Setup is not coordinator-only yet

The `bar` list says Setup is shown to the coordinator group only, but `lib/access.ts` (`mayUse(me, "setup")`, Nimish 22 Oct 2026:
"don't differentiate that") gives every member of staff Setup today, and a change of who may see what is not this slice. The door
follows `mayUse`; acting as an educator puts it away. Acting as itself is a coordinator's (`me.role === "coordinator"`).
"How it works" (`the_map`) and "Report a problem" are links at the foot of every page, not in the bar.
