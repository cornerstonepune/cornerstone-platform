# CP-22: a draft goes live

Branch `cp-22-build` from main. Scope `specs/CP-22` (CP-21's locked scope on PR #495, renumbered; issue #496), design
`specs/CP-22/design.md`, plan `specs/CP-22/plan.md`.

## What was built
- Migration `20270125160000_a_draft_goes_live.sql`: `timetable_slot.fortnight_id`; the slot key now includes it (nulls not
  distinct) so a dated row on the frame's own first day does not collide with the frame row; a partial index of one dated
  row per class, period and date; `timetable_live` (append-only: class, fortnight, run, state hash, discarded, reason, who,
  at); setting `timetable.go_live_group` per school (`everything`); `access_table` row (school-wide).
- `w2_print/tt_live.py` (checks, layer, writes, record) and `tt_live_plan.py` (which sessions move where, what stops the
  step). `tt_generate.input_text` gives the FET input for the rules as they stand, to see whether a draft is stale.
- `engine timetable go-live` (`cli_timetable.py`), with `--dry`, `--reason`, `--discard-changes`.
- `k2_day.py`: a dated row wins over the frame row. `k2_timetable_sql.apply`: refuses a load that reaches a live fortnight.
- Who: the person is looked up with `public.staff_of_email` (a staff id) and must hold a current grant whose role is in the
  access group named by `timetable.go_live_group`. `internal.resolve_staff()` is the signed-in browser session's lookup and
  there is none on the command line; the group check uses the same grant and group tables it reads, with the school's own
  day from `educator_gate.school_today` (the `school.time_zone` setting), never `current_date`.

## Decisions that differ from the design
- The session key is **not** made deferrable. Postgres refuses a deferrable key as an `on conflict` arbiter (checked: "ON
  CONFLICT does not support deferrable unique constraints/exclusion constraints as arbiters"), and an existing loader test
  requires the loader's `on conflict do nothing` on every insert and may not be edited (proof 8). Sessions that change place
  are instead taken out together with their materials links and put back at the same id in their new cells, in one
  transaction (`tt_live._write`). Nothing else references a session.
- The stale-rules check rebuilds FET's input text from the rules now (`tt_generate.input_text`) and compares it with the
  run's `input_text`, using the run's own FET version; no FET binary is run to go live.

## Open: one locked proof helper conflicts with CP-11's table
Proof 8's loader test inserts a `timetable_run` row through a helper that fills every required column with a placeholder, so
`solve_seconds` is 0, and CP-11's own check on that column (`solve_seconds > 0`) refuses the row. The product code is not
involved: with a temporary column default of 1 on a scratch database the same test passes. A fix needs Nimish to unlock
CP-22 and let the helper name `solve_seconds`.
