## PR A: the pure functions (build session, 17 Nov 2026)

`w2_print/tt_offer.py` (`offers`, `live`, `pointer`, `taught`, `next_after`) and `w2_print/tt_fill.py` (`spread`, `same_as_last_week`,
`suggest`). Pure: no database, no model; tests `tests/test_tt_offer.py` (Done when 1 to 3) and `tests/test_tt_fill.py` (4 to 7). They run nightly,
not in the core. They read plain rows, so the columns do not need to exist yet; the loader and writer come with PR C, after the migration (PR B).

Decisions:
- **A one-off unit never moves the sequence.** The pointer is the last lesson whose objective is in a live, non-one-off unit, so a field-visit day
  does not reset "next up". One-off units sit last in "all of the subject".
- **`one_off` is an input flag.** Code must not hold a list of noise units (rule 1). The loader in PR C reads it from a setting row (unit names or
  patterns such as "see source LO", "Field Visit…", "…(Weekly)"), seeded machine-made. Live G2 Maths shows the noise: "Quiz _Every alternate
  week", "Weekly Mental Math Sessions", "Field Visit to a Bank", "Celebrating Ganit Diwas", "Projects", "see source LO".
- **Suggest walks the lessons still to come in order.** A person's lesson with an objective moves the sequence on from there. A person's lesson
  with only an activity is left alone and does not move it. The job stops at the end of the subject and leaves later lessons as they are.
- **"Same as last week"** takes the subject's lesson seven days earlier in the same period. Failing that, it takes that day's first lesson of the
  subject. It refuses in words when there is none or nothing was chosen.
- **Not proven yet:** Done when 7's "unchanged by a re-publish". That needs the writer and the `session.source` column, so the proof goes in PR C
  with a database test.

**Lessons from Phase 1 (each cost a CI run):**
- `bin/check` does **not** run the core. Run `packages/engine/tests/core.txt` on a clean database before pushing (`grep -v '^#' tests/core.txt | grep -v '^$'
  | xargs uv run pytest`), and `playwright test --list --grep @core` must stay at 120. The engine core is 230.
- A test added to a file that `core.txt` names as a whole file (e.g. `test_tt_pattern_routes.py`, `test_tt_pattern.py`) raises the core. Put new tests in
  files of their own.
- Every exported server action in `app/**/actions.ts` must call `requireStaff()` in its own body (`test_web_gate`).
- Local browser runs regenerate committed screenshots (`docs/notes/img`, and other specs' `docs/screens/**`): commit only your own `cp74-*`.
- A local database that browser specs have written to makes engine tests that look at "every class with a pattern" fail. Use a clean one
  (`bin/testdb fresh postgresql://postgres:pw@localhost:5432/<name>`, about 10 minutes, wait until it finishes) for the core.
- Specs need classes of their own in a year of their own (new each run); the `u110` to `u112` specs show how.
- `test_web_identity` fails in this container (Node cannot resolve an extension-less import); it is environmental.
