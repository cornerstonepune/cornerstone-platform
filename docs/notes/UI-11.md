# UI-11: setup content screens (curriculum, skills to approve, question bank, a question)

Branch `ui-11-setup-content`, issue #522, PR #582 (draft). Scope: `specs/UI-11/spec.md`. Tests: `apps/web/tests/u74-setup-content.spec.ts` (13, pass on a local copy built with `bin/testdb fresh`). Open points: issue #585.

## State (10 Nov 2026)

Built, on the frame and the blocks, old pages untouched:
- `/setup/curriculum`: one list (K2 activities and grade 1 to 4 skills) under one filter row; drafts card and the main action; offers table with Yes / No per row.
- `/setup/skills/approve`: eyebrow is the count; Approve per row (`approveSkills`, `only`); Levels-to-review tab (the old page's body, `levels-tab.tsx`); the charges fold.
- `/setup/question-bank`: ten rows then pages; statistics behind a fold (by grade and level).
- `/setup/question-bank/[key]`: card trio, About fold, Correct the wording (needs a reason, the engine refuses without), Remove (reason required).
The inventory (`screens.json`) entries are rewritten for these four and `tests/inventory-fixtures.ts` gives the checker a taught class, the K2 gate open, two offers and a question key. The inventory passes for all four screens (16 tests, `SLICE=UI-11`) with the `drive` hints of PR #578 declared on Yes, No, Approve, Correct the wording and Remove; their fixtures and checks are in `tests/inventory-fixtures.ts` (the checks wait for the rows: a press returns before the engine has finished). The last commit adds `UI-11` to `merged_slices`.

Not done, by the orchestrator's ruling (same as UI-4): the 308 folds. The old pages that hold controls no element lists (/asks, worksheets, bank proposals, "Approve this table") stay live; a follow-up, UI-11b, carries those onto the new screens and retires the old pages one at a time. Done-when 2 is therefore not met by this PR.

Known: the question screen's drives are timing-sensitive on a database that has been used before (the engine's work after a press lingers); on a fresh database they pass.

## Decisions

| Choice | Reason |
|---|---|
| The first row's Approve / Open link carries `data-ux="action"`; the screen passes no `action`. | The element list has no separate main action, so it is one of the listed controls (as UI-4 did). |
| Curriculum asks the K2 gate softly (`gateFor`): closed means the skills only, not a 404. | The screen holds more than the K2 pages; a closed K2 gate must not hide the skills. |
| Yes / No and Approve carry the row's name as hidden text. | The inventory keys controls by text and place, so identical buttons collide; a screen reader gains the name too. |
| `FilterBar` selects take `max-w-full`. | A long skill name in a dropdown pushed the page sideways at 400 px. |
| `Cards` takes an optional `body` and an optional link. | The question's cards hold a picture and a table; no block fitted, and this is the same block. |
| The shared bank actions take a `base` field. | The old library pages stay live until the folds are ruled on, and must keep redirecting to themselves. |
| Statistics are by grade and level, not by skill. | A second paged table inside the fold would be a control the list does not name. |

## Left out on purpose (nothing deleted: the old routes are live)
Bank proposals (remove / keep / adopt), "Approve this table", the worksheet library and taxonomy, `/asks`. Issue #585.
