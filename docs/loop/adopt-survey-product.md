# Adoption survey: product, architecture, screens (2026-11-23)

Read-only survey for `loop-adopt` (PROJECT.md §1–4, GLOSSARY.md). Check before relying on it. **Headline:** README, ARCHITECTURE.md and SPEC.md describe a maths assessment engine with "six screens" and 32 tables. The code is now a wider school system: 56 pages and 87 tables, covering timetable, lessons, curriculum, materials, money and stock for K2 and G1–G4.

## Product
- **Problem:** educators can't see, child by child and skill by skill, what each child has secured or keeps getting wrong (SPEC §1).
- **Users:**
  - Educator: says what was taught, approves papers, photographs them back, confirms doubts, sees each child. About 10 minutes a week.
  - Coordinator: approves skills, timetables and reports; sees all classes.
  - Operations lead or founder: approves claims; founders pay.
  - Store keeper (`ops`, one campus): stock.
  - Parents never sign in.
- **Must do:**
  - A code-checked question bank at Easy, Medium, Hard and Advance.
  - A QR paper for each child from their graph, plus spares and a key, approved before print.
  - Reading photographed papers: QR, then digit reader, then marking by key, with a confirm queue.
  - Append-only evidence feeding a skill graph with six states.
  - The class picture, home papers and parent reports, with two approvals per line.
  - School operations: K2 voice notes, the timetable (FET / CP-SAT), lessons, materials, catalogue, money and stock.
- **Will not do:**
  - Guess a level without evidence.
  - WhatsApp inbound photos, an adaptive tutor, Kreeyo, a second store (SPEC §15).
  - Approve-all (ux rule 13).
  - Rank educators.
  - Show a level to a child.
  - Use the words taxonomy, rung or kind on an educator's screen.
- **Done for v1:**
  - At least 95% marking agreement with educators, and the class card changes a Monday decision.
  - The print pack needs no sorting.
  - The confirm queue takes under 2 minutes per class.
  - Four assessments show a trend.

## Architecture
- **Engine:** Python 3.12 (FastAPI + `bin/engine`). Runs on AWS Lightsail in Mumbai, in Docker behind Caddy at `<ip>.sslip.io`, with a standby (`deploy/compose.server.yml`). `docs/deploy.md` saying "not deployed" is stale.
- **Web:** Next.js (with breaking changes, `apps/web/AGENTS.md`) on Vercel `bom1`, https://cornerstone-assessment.vercel.app. A merge to main publishes. It calls the engine only via `apps/web/lib/engine.ts`, generated by `bin/engine contract`.
- **Database:** Supabase Postgres in `ap-south-1`; migrations only; settings and prompts are seeded rows.
- **Sign-in:** school email and password, or an emailed link over SMTP. Staff list only (`pii.staff`). The cookie is `cs_staff`.
- **n8n:** wiring only (`n8n/workflows/f1…f6`). Whether it is hosted is open (SPEC §14 item 5).
- **Modules** (`workflows.json`, held by `test_layout.py`):
  - `w1_bank` (N1–N2)
  - `w2_print` (N4–N7, with the week declaration and timetable)
  - `w3_read` (N3, N8–N10)
  - `w4_close` (N11–N12)
  - shared: `assess`, `core`, `skills` (CP-54), `adapters`, `checks`; doors `api/` and `cli.py`
- **Adapters:**
  - `llm.py`: Claude, else Gemini. Prompts are rows; every call logs a `flow_run` with its cost; `llm_budget.py` holds the cap.
  - `digits.py`: PaddleOCR. Vision was rejected because it "fixes" wrong answers (ADR 0019).
  - `ocr.py`: Textract.
  - `speech.py`: Sarvam.
  - `jev.py`: TypeSafe Jev.
  - `fet.py` (AGPL) and `cpsat.py`: timetable solvers.
  - Drive, SMTP and WhatsApp are reached via n8n.
- **Security:**
  - Separate database roles for the two services, `app_engine` and `app_web` (ADR 0046).
  - Row access from `access_role_group`, `access_reach` and `access_table`, turned into policies by `internal.apply_conventions()`. An educator sees their own classes; a coordinator sees all (ADR 0101).
  - The website never reads `pii`; the engine reads it through logged accessors (`access_log`).
  - "Acting as" changes the view, never the permission.
- **Non-negotiables:**
  - Nothing structural in code; prompts are rows plus an eval.
  - `evidence_event`, `approval`, `change_log` and `stock_move` are append-only.
  - Three signals stay distinct.
  - A number is never a model's last word.
  - Every table has an `access_table` row.
  - No file over 400 lines.
  - Machine-made data never overwrites a person's edit.

## Core data flows
- **Bank:** skill set → prompt writes items → code verifies → `approved`. An item is retired by an `approval` of kind `item`.
- **Papers:** week declaration → prescription from `child_skill_state` → `sheet_instance` (QR `CS` + 6 hex) → pack → educator approves → print.
- **Reading:** photo → `capture` → digits → key lookup → `item_result` → person confirms → `evidence_event` → nightly `child_skill_state`.
- **Close:** class picture, home paper and parent report (two approvals per line, consent) → next prescription.
- **K2:** voice note → `educator_note` → claims → observed states.

## Glossary candidates
- **People:** educator (not "teacher" to parents); coordinator; staff; campus (Gurukul K2–G4, Neev PG–K1); acting as (a view, not a permission).
- **Skills and levels:**
  - skill (registry id as issued, e.g. `NUM.OPS.01`); skill set (a skill as what a child can do, four levels)
  - difficulty: Easy, Medium, Hard, Advance (never L−/L0/L+ or Level A/B)
  - rung: R1–R14, X1, X2, never on an educator's screen
  - band: G1–G4
  - case tags / taxonomy case: derived by code, never typed
  - signal: Foundational, Conceptual, Procedural, Application, Stretch
- **Making questions:**
  - blueprint (the slots a paper asks for); item / question; template (the unit of trust)
  - misconception (`M_…` procedural, `M0nn` external); predictor (computes the wrong answer)
  - verifier (code checks what a model wrote)
  - exchange / regroup (never "borrow")
  - three signals: blank, wrong, wrong-with-working
- **Papers:** week declaration; prescription; sheet template versus sheet instance (QR); spare; pack; home paper; custom paper.
- **Reading and marking:** capture / scan; reader (PaddleOCR, not vision); confirm queue / answers to check / sign off; item result.
- **Evidence and the child's picture:**
  - evidence_event (append-only; a correction supersedes)
  - child skill state: not_enough_yet, patterned, emerging, practising, secure, stretch_ready; written or observed
  - status colours: green, amber, red, grey; a child is never shown red
  - class card / class picture (built on request); parent note / report (two approvals, consent)
- **Records:** approval (no approve-all); curriculum proposal; eval case; prompt (versioned row); flow_run; change_log; machine-made versus person (`source`).
- **Curriculum and lessons:** learning objective ("the atom"); activity / strand / head; fortnight / week A/B / frame / pattern; session / lesson / period; voice note / educator note (children said as numbers).
- **Materials and money:** materials line; catalogue item; stock move; buy list; claim.
