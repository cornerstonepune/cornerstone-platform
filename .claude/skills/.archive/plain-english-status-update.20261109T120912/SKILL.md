# Status updates for a non-technical founder: answer first, plain bullets, no codes

Open with the direct answer to the question asked, such as "Nothing is needed from you" or "Yes, faster, but not yet fast enough". Then give three to six bullets, each one a plain outcome: what changed for users, what is proven, what is still open.

- Use everyday words. Say "the voice notes feature", not a ticket or spec ID. Leave out file names, migration numbers, branch and pull request jargon, and hook or tool messages unless he asks.
- Name at most one decision he must make, in one line. If there is none, say so.
- When he asks why work is stalled, answer in one sentence: the step that is waiting, the one thing it waits for, and the rule that makes it wait (quote the rule in his words, not the file name). No issue numbers, spec IDs, agent names or label names, even when the rule uses them. Restate the ask once, plainly, at the end.
- Keep it under about ten lines. Do not narrate the steps you took.
