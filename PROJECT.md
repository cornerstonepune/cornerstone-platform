## 1. Product (≤15 lines)
- **Problem:** educators can't see, child by child and skill by skill, what each child has secured or keeps getting wrong; and the school's running (timetable, materials, money) lives in paper and chat.
- **Users:** educator (says what was taught, approves papers, photographs them back, settles doubts: ~10 min a week) · coordinator (approves skills, timetables, reports; sees all classes) · operations lead / founder (approves claims; founders pay) · store keeper (stock, one campus). Parents never sign in.
- **Must do (v1):**
  - A code-checked question bank at Easy / Medium / Hard / Advance.
  - A QR paper per child drawn from their skill picture, plus spares and a key, approved before print.
  - Read photographed papers (QR → digit reader → key) with a confirm queue; nothing a model reads is final without a person.
  - Append-only evidence feeding each child's skill state; the class picture, home papers and parent reports (two approvals per line).
  - School operations: K2 voice notes, timetable (FET / CP-SAT), lessons, curriculum, materials and catalogue, claims and stock.
- **Will NOT do (v1):** guess a level without evidence · WhatsApp inbound photos · adaptive tutor · Kreeyo · a second store · approve-all · rank educators · show a level to a child · say taxonomy, rung or kind on an educator's screen.
- **Done for v1 means:** ≥95% marking agreement with educators; the class card changes a Monday decision; the print pack needs no sorting; the confirm queue takes <2 min per class; four assessments show a trend.

## 2. Architecture (≤20 lines)
- **Engine:** Python 3.12, FastAPI + `bin/engine` CLI (`packages/engine`). Docker behind Caddy on AWS Lightsail, Mumbai, with a standby (`deploy/compose.server.yml`). Why: all maths, reading and rules in one tested place.
- **Web:** Next.js + TypeScript (`apps/web`) on Vercel `bom1`; a merge to main publishes. Calls the engine only through `apps/web/lib/engine.ts`, generated by `bin/engine contract`.
- **Database:** one Supabase Postgres (`ap-south-1`). Schema changes only as numbered files in `supabase/migrations/`; settings and prompts are seeded rows (`supabase/seed/`).
- **Shape:** engine folders follow `workflows.json` (held by `tests/test_layout.py`): `w1_bank` (N1–N2), `w2_print` (N4–N7), `w3_read` (N3, N8–N10), `w4_close` (N11–N12); shared `assess` (pure maths), `core`, `skills`, `checks`; doors `api/` and `cli.py`; outside calls only in `adapters/`.
- **External systems:** Claude, else Gemini (`llm.py`, every call logged in `flow_run` with cost, capped by `llm_budget.py`) · PaddleOCR digits (`digits.py`; vision rejected, ADR 0019) · Textract (`ocr.py`) · Sarvam speech (`speech.py`) · FET (AGPL) and CP-SAT timetable solvers · Drive, SMTP and WhatsApp only via n8n (`n8n/workflows/`, trigger/wait/notify only).
- **Sign-in:** school email + password, or an emailed link. Staff list only (`pii.staff`), cookie `cs_staff`.
- **Security model:** separate DB roles `app_engine` and `app_web` (ADR 0046). Row access from `access_role_group` / `access_reach` / `access_table`, applied as policies by `internal.apply_conventions()` (ADR 0101): an educator sees their own classes, a coordinator all. The website never reads `pii`; the engine reads it through logged accessors (`access_log`). "Acting as" changes the view, never the permission.
- **Non-negotiables:** nothing structural in code (prompts are rows + a scored eval) · a number is never a model's last word · `evidence_event`, `approval`, `change_log`, `stock_move` are append-only · blank / wrong / wrong-with-working stay distinct · every table has an `access_table` row · machine-made data never overwrites a person's edit · no file over 400 lines · names only in `pii`; scans never in git or logs.

## 3. Data model
- **Source of truth:** `db/schema.sql` (dumped from the 183 migrations, ADR 0104). Don't copy columns here.
- **Entities and why they exist** (the ones the flows hang on; 87 tables in all):

| Table | Holds | Key relations | Notes |
|---|---|---|---|
| `pii.child`, `pii.staff` | names, emails, passwords | → `public.child`, `public.staff` | only place names live |
| `child`, `school_class`, `enrolment`, `campus` | who is in which class | child → enrolment → school_class | app tables carry `child_id` |
| `skill`, `skill_level`, `registry_skill`, `skill_prerequisite` | what a child can do, at four levels | level → skill | registry ids as issued (`NUM.OPS.01`) |
| `learning_objective`, `activity`, `topic`, `subject`, `grade` | the curriculum | activity ↔ objective ↔ skill | ~3,427 objectives, ~3,915 activities live |
| `item`, `misconception`, `question_type`, `prompt`, `eval_case` | the question bank and how it's made | item → skill_level | ~51,600 items live |
| `sheet_template`, `sheet_instance`, `prescription` | papers: the design, the printed QR copy, why this child got it | instance → child, template | QR `CS` + 6 hex |
| `capture`, `item_result`, `read_correction` | photographed pages and what was read | result → capture, item | scans never in git |
| `evidence_event` | every signal about a child on a skill | → child, skill | append-only; corrections supersede |
| `child_skill_state` | the six-state picture per child per skill | → child, skill | rebuilt nightly (not yet on live, #557) |
| `approval`, `parent_note`, `report_item`, `consent` | people's sign-offs and reports | → many | append-only; no approve-all |
| `period`, `session`, `timetable_rule`, `timetable_run`, `fortnight` | timetable and lessons | period → school_class | |
| `pii.educator_note`, `pii.note_claim` | K2 voice notes and the claims drawn from them | claim → child | |
| `material_item`, `materials_line`, `stock_move` | catalogue, needs, stock | line → activity | `stock_move` append-only, 0 rows live |
| `expense` | staff claims and their path to paid | → staff | 0 rows live |
| `flow_run`, `change_log`, `access_log`, `web_error` | audit and cost | | |

- **Core flows:** bank: skill → prompt writes items → code verifies → approved. Papers: week declaration → prescription from `child_skill_state` → `sheet_instance` → pack → educator approves → print. Reading: photo → `capture` → digits → key → `item_result` → person confirms → `evidence_event` → nightly `child_skill_state`. Close: class picture, home paper, parent report (two approvals per line) → next prescription.
- **Invariants** (tests exist in `packages/engine/tests/`, e.g. `test_access_every_table.py`, `test_access_keys.py`; which are in `tests/core.txt` is unchecked): evidence and approvals are append-only · every table has an `access_table` row and policies · the web role cannot read `pii` · blank, wrong and wrong-with-working are three signals · a person's edit is never overwritten by machine data · prompts are rows, not code.
